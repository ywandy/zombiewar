# 模块化玩家角色资产生产设计

## 目标

根据游戏开始页角色的粗粝末日漫画风格，生产十个可直接替换现有玩家占位模型的正式角色：男性与女性各覆盖机枪手、突击手、医疗兵、爆破兵、防爆兵。角色必须共用当前 `Characters_Lis_SingleWeapon.gltf` 的 43 骨骼，并能播放其中全部 20 个动画。

另外生产七件独立武器：RPG、AK-47、M4A1 卡宾枪、战术匕首、HK-45C 紧凑型战术手枪、地雷、MP-5 冲锋枪。武器保持独立网格，通过骨骼挂点装配，不与手掌或人体生成成粘连网格。

本轮替换 `resources/characters/character_catalog.tres` 中现有四个共用模型的占位角色。旧模型和旧定义是否删除，实施时先做全仓引用检查；只有无引用且不再承担默认回退职责的资产才允许删除。

## 已确认的视觉方向

采用“B · 可玩漫画”风格：约 4.5 头身，大头、块面塑形、粗黑轮廓、手绘磨损材质，保留开始页的紫黑军装与红色识别元素。四肢比开始页插画略长，以便现有骨架驱动、持枪动作和 2.5D 俯视战斗轮廓保持清楚。

四视图统一使用正交相机、中性 A-Pose、相同画布尺寸、相同人物尺度和无透视变形的纯色背景。角色主体不持武器，手指保持可蒙皮的放松张开状态。前、左、右、后四张图必须保持脸型、发型、服装裁片、附件数量、颜色和磨损位置一致。

## 角色与展示装备矩阵

| 兵种 | 默认展示武器 | 关键轮廓语言 |
| --- | --- | --- |
| 机枪手 | MP-5 | 弹匣袋、加厚手套、紧凑弹药背带 |
| 突击手 | AK-47 | 中型胸挂、护肘、红色识别带；M4A1 作为备选展示武器 |
| 医疗兵 | HK-45C | 医疗包、止血带、白色或浅色医疗识别面，不使用依赖字体的装饰符号 |
| 爆破兵 | RPG | 加强肩垫、爆破工具包，地雷挂在腰间 |
| 防爆兵 | 战术匕首 | 重型防护、宽肩、护臂；M4A1 作为备选展示武器 |

男女版本共享兵种语言，但脸型、发型、肩宽、腰胯和服装裁片应有清楚差异。两者都必须遵守同一骨骼比例边界，不能用极端体型破坏动画。

## 资产架构

### 共享基体

生产 `male_base` 与 `female_base` 两套共享蒙皮基体。基体负责头、躯干、四肢、手脚以及稳定的骨骼权重。两套基体都绑定到现有 43 骨骼，并保留当前 20 个动画的名称与可播放性。

基体不会在运行时动态换装。模块化的意义是降低生产和修整成本：各角色在 Blender 中由共享基体和兵种部件装配，最终烘焙并导出为十个独立 GLB，以维持简单、可靠的 Godot 导入和 `model_scene` 引用。

### 兵种部件

每个兵种至少拆分为：

- 头脸与发型或头盔；
- 上身护具或胸挂；
- 背包；
- 腰部和腿部附件；
- 必要的肩、肘、膝防具。

贴身且会随关节明显变形的部件参与蒙皮；硬质背包、腰包和武器优先通过对应骨骼挂点刚性绑定。部件命名必须包含性别、兵种、部位，例如 `male_assault_vest`。

### 武器

七件武器各自生成、清理和导出，原点、前向和手握基准一致。实际开火、伤害、射线、弹药和模拟逻辑继续由现有武器场景与脚本负责；新模型只替换表现层。RPG、AK-47、M4A1、HK-45C、MP-5 与匕首需要右手握持挂点；长枪另设左手辅助握持基准与背部收纳挂点。地雷需要腰部收纳挂点和地面放置原点。

## 生成流水线

### 1. 样板门槛

先完整制作“男性突击手 + AK-47”样板。样板通过图像一致性、Tripo3D、Blender 装配、骨架、动画、面数和 Godot 导入验收之前，不启动其余九个角色的批量生成。

### 2. 四视图生成

使用 `gpt-image-2`。开始页截图作为风格参考图，不作为编辑目标；已通过的正视图作为身份和服装结构参考。先生成正视图，再以开始页截图和已通过正视图为参考派生左、右、后视图。

每个角色和武器保留独立提示词及最终四视图文件。四张图不能拼成一张图提交。视图质量不合格时只重做失败视角，并再次检查四图一致性。

### 3. Tripo3D 多视图建模

使用当前 43Coding 网关的 `multiview_to_model` 任务。已于 2026-08-13 真实提交四图任务 `de851dff-07ec-4a19-9135-a89ee3a02e57` 并成功得到 GLB，确认技能文档中仅列 `image_to_model` 的说明已过期。

`files` 固定按以下接口顺序提交：

1. 前；
2. 左；
3. 后；
4. 右。

每个输入是独立 `{type, url}` 文件对象。正式任务使用四张不同方位图，不复用同一图片。人体基体、兵种部件和武器分别建模，避免人体与装备粘连。Tripo3D 同时运行的生成任务控制在 2–3 个，按批次推进，避免触发并发或额度限制。

### 4. Blender 装配

通过 Blender MCP 执行可重复的导入、命名、尺寸与朝向统一、原点校准、网格清理、材质整理、骨架转移、权重修整和导出。保留一个样板 `.blend` 作为装配母版。

模型以前视图面向 Godot 玩家模型的视觉前向；最终转换规则以当前 GLTF 的实测坐标为准，不凭约定猜测。基体先对齐当前 43 骨骼，再转移或重新绘制权重。附件完成装配后检查肩、肘、腕、髋、膝和背包区域的穿模。

样板至少播放并检查：`Idle`、`Idle_Gun`、`Walk_Gun`、`Run_Gun`、`Slash`、`Stab`、`HitReact`、`Death`。完整自动检查仍需确认全部 20 个动画存在且可加载。

### 5. 受控并发

通过样板门槛后，按可独立产出的角色、兵种部件与武器并发生成图片和准备任务。Tripo3D 限制在 2–3 个同时运行的任务。Blender 装配共享同一个母版规范，各角色可独立准备，但最终导出前集中核对骨架、材质、挂点和命名，避免并发过程引入标准漂移。

## 面数与材质预算

- 每个装配后角色：不超过 30,000 三角面；
- 每件武器：不超过 5,000 三角面；
- 以 Web 导出为性能基线；
- 优先用法线、粗糙度和手绘颜色表达磨损，不用高面数刻出细小刮痕；
- 尽量将单个角色的材质槽和纹理数量保持在少量稳定集合中，具体上限由样板的 Godot draw-call 检查确定；
- 透明材质只在无法用不透明剪影表达时使用，头发优先做块状实体发束。

若 Tripo3D 输出超过预算，先移除不可见内部面和合并重复部件，再做保轮廓的减面；不能以破坏手指、脸部、武器枪管或兵种关键轮廓的方式强行达标。

## Godot 接入

十个角色使用稳定 `StringName` ID：

- `male_gunner`、`female_gunner`；
- `male_assault`、`female_assault`；
- `male_medic`、`female_medic`；
- `male_demolition`、`female_demolition`；
- `male_riot`、`female_riot`。

新建十个 `CharacterDefinition`，其 `model_scene` 分别指向对应角色 GLB 场景。`character_catalog.tres` 只登记这十个新角色，用它们替换现有四个占位定义。默认角色 ID 必须更新为新目录中实际存在的 ID。

职业数值、本命武器和被动能力沿用现有 `CharacterDefinition`、玩家装配和模拟配置路径。突击、医疗、爆破、防爆基于现有职业语义迁移；机枪手新增一组角色定义配置。七件武器全部交付独立模型；其中可映射到现有 `pistol`、`smg`、`rifle`、`knife` 玩法资源的模型可以替换或扩充表现层，RPG 和地雷等当前没有对应攻击机制的资产只作为预览、挂件和后续玩法储备。本设计不新增 RPG、地雷或其他武器的伤害、弹药、投放、爆炸、模拟或联机逻辑。

在线模式继续只传角色 ID。未知 ID 或旧占位 ID 必须按现有内容校验规则拒绝入局，绝不静默回退。此改动不触碰模拟 tick、帧协议、导航或世界阻挡逻辑。

## 产物与溯源

每个角色或武器都保留：

- 最终生成提示词；
- 前、左、右、后四视图；
- Tripo3D 任务 ID 和原始下载地址记录；
- 原始 Tripo GLB；
- 清理与装配用 `.blend`；
- Godot 使用的最终 GLB；
- 转台或固定视角预览图；
- 面数、材质槽、骨架和动画验收记录。

生成资产放入 `assets/characters/` 与 `assets/weapons/` 下的清晰子目录；生产记录和提示词放入 `docs/assets/`。临时上传 URL 不作为长期溯源，模型完成后立即下载到仓库外暂存区，再将选定最终资产复制进仓库。

## 失败隔离

- 四视图身份或服装不一致：只重做失败视角；
- Tripo3D 网格错误：只重做对应基体、部件或武器；
- Blender 动画穿模：只修受影响角色的权重或附件形状；
- 面数超标：先清理内部面，再局部减面；
- Godot 导入或动画名失败：停止该角色接入，不回退到默认模型掩盖错误；
- Tripo3D 并发或额度限制：保留 task ID 和生成清单，降低批次并发，不重复盲目提交。

## 验收

### 样板验收

男性突击手样板必须满足：

- 四视图是同一角色、同一服装和同一比例；
- 人物与 AK-47 是独立资产；
- 角色不超过 30,000 三角面，AK-47 不超过 5,000 三角面；
- 绑定到现有 43 骨骼；
- 全部 20 个动画存在；
- 重点动画无明显关节破裂、手掌脱枪、护具穿模或背包漂移；
- Godot 能加载模型、播放动画并装配现有武器场景；
- 游戏内 2.5D 视角下轮廓仍与开始页风格一致。

### 全批次验收

- 十个稳定角色 ID 唯一且全部命中目录；
- 未知 ID 返回 `null`，不回退；
- 十个 `model_scene` 均可实例化；
- 每个角色骨架、动画、材质和挂点完整；
- 七件武器面数、原点、前向和握持基准一致；
- 运行 Godot headless 编辑器导入检查；
- 运行 `tools/validation/validate_character_catalog.gd`；
- 新增中文显示文本时运行 `tools/validation/validate_ui_font_coverage.gd`，并逐个确认相关 Control 实际绑定项目字体；
- 生成角色选择页或游戏内固定机位截图，由用户复核最终视觉结果。

## 非目标

- 不在本轮重做现有 20 个动画；
- 不实现运行时自由换装系统；
- 不修改伤害、弹道、模拟 tick、联机帧协议或导航；
- 不以 70 个“性别 × 兵种 × 武器”完整角色模型作为交付；
- 不把四视图拼图冒充 Tripo3D 多视图输入；
- 不依赖 Godot 的系统字体回退或未验证的默认内容回退。
